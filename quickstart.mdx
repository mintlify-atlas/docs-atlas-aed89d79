---
title: "Quickstart"
description: "Get up and running with RDMA in minutes using Soft-RoCE (RXE), which requires no special hardware."
---

The fastest way to try rdma-core is with **Soft-RoCE** (`rdma_rxe`), a software RDMA driver that runs over any existing Ethernet interface. No InfiniBand or RoCE hardware is required.

<Steps>
  <Step title="Install dependencies">
    Install the build dependencies for your distribution.

    <Tabs>
      <Tab title="Debian/Ubuntu">
        ```bash
        apt-get install build-essential cmake gcc libudev-dev libnl-3-dev libnl-route-3-dev ninja-build pkg-config valgrind python3-dev cython3 python3-docutils pandoc
        ```
      </Tab>
      <Tab title="Fedora/CentOS 8">
        ```bash
        dnf builddep redhat/rdma-core.spec
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Build rdma-core">
    Clone the repository and run the quick-start build script. This configures cmake with `IN_PLACE=1` and builds using ninja (or make as a fallback).

    ```bash
    git clone https://github.com/linux-rdma/rdma-core.git
    cd rdma-core
    bash build.sh
    ```

    After a successful build, programs are in `build/bin/` and shared libraries are in `build/lib/`.
  </Step>

  <Step title="Load the RXE driver and create an RDMA device">
    Load the `rdma_rxe` kernel module, then attach it to an existing network interface. Replace `eth0` with the name of your interface.

    ```bash
    modprobe rdma_rxe
    rdma link add rxe_eth0 type rxe netdev eth0
    ```

    <Note>
      A recent version of `iproute2` is required for the `rdma link` command.
    </Note>

    If you have a Mellanox HCA on the same machine, unload its kernel module first to avoid conflicts:

    ```bash
    modprobe -rv mlx4_ib
    # or for ConnectX-4 and newer:
    modprobe -rv mlx5_ib
    ```
  </Step>

  <Step title="Verify the device is available">
    Confirm that your new RXE device appears in the system.

    ```bash
    ibv_devices
    ```

    Or use the `rdma` command:

    ```bash
    rdma link
    ```

    You should see a device named `rxe_eth0` listed and in `ACTIVE` state.
  </Step>
</Steps>

## Open a device in C

The following example uses `libibverbs` to list available RDMA devices and open the first one.

```c open_device.c
#include <stdio.h>
#include <infiniband/verbs.h>

int main(void)
{
    struct ibv_device **dev_list;
    struct ibv_context *ctx;
    int num_devices;

    dev_list = ibv_get_device_list(&num_devices);
    if (!dev_list) {
        perror("ibv_get_device_list");
        return 1;
    }

    printf("Found %d RDMA device(s)\n", num_devices);

    if (num_devices == 0) {
        fprintf(stderr, "No RDMA devices found\n");
        ibv_free_device_list(dev_list);
        return 1;
    }

    printf("Opening device: %s\n", ibv_get_device_name(dev_list[0]));

    ctx = ibv_open_device(dev_list[0]);
    if (!ctx) {
        perror("ibv_open_device");
        ibv_free_device_list(dev_list);
        return 1;
    }

    printf("Device opened successfully\n");

    ibv_close_device(ctx);
    ibv_free_device_list(dev_list);
    return 0;
}
```

Compile and run with:

```bash
gcc open_device.c -o open_device -libverbs
./open_device
```

## Open a device in Python (pyverbs)

The same operation using the **pyverbs** Python bindings:

```python open_device.py
from pyverbs.device import Context, get_device_list

devices = get_device_list()
if not devices:
    raise RuntimeError("No RDMA devices found")

print(f"Found {len(devices)} RDMA device(s)")

dev = devices[0]
print(f"Opening device: {dev.name.decode()}")

ctx = Context(name=dev.name.decode())
print("Device opened successfully")

attr = ctx.query_device()
print(f"  Max QPs:  {attr.max_qp}")
print(f"  Max CQEs: {attr.max_cqe}")
```

<Tip>
  pyverbs is built automatically by `build.sh` when Cython and Python development headers are available. The module is located at `build/lib/pyverbs/`.
</Tip>
